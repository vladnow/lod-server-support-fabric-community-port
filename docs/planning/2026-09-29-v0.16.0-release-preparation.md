Updated 2026-09-29 after the release follow-up review. **All five final release candidates pass local preflight.** This report and its [artifact manifest](../implementation/2026-09-29-v0.16.0-release-preparation.json) supersede the earlier candidate hashes and validation summary. Nothing has been pushed, merged, tagged, published or deployed during this preparation; hosted CI remains the next release gate. The user authorized publication of LSS and VSS on 2026-09-29; the publishing scope below supersedes the earlier LSS-only preparation.

[Proposed release notes](release-notes-v0.16.0-proposed.md) and the per-line notes under `v0.16.0-release-notes/` contain the requested concise wording.

## Follow-up changes

- Named the removed `/lsslod set` command and its replacement: edit YAML, then run `/lsslod reload`.
- Made the legacy migrator accept the old Gson loader's comments, unquoted/single-quoted syntax, legacy separators, root-field last-value behavior and boolean string conversion. YAML remains strict. UTF-8, depth/node/numeric bounds, one-object/full-input checks and rejection of corrupt structures remain enforced; failed migrations preserve source files.
- Documented one-way migration: v0.15.x reads the retained JSON and ignores YAML edits. Desired changes must be ported back to JSON before downgrading.
- Corrected the Chinese item to describe translations for new settings strings, removed internal changelog detail, and removed NeoForge claims from the 1.21.10/1.21.11 notes. The four entries previously removed at the user's request remain absent.
- Reload-enabled backfill now waits for an actual pending startup sweep using the existing bounded worker wait. It does not turn genuinely unhealthy stores into automatic retry loops. The health check ordering tolerates the sweep completing between reads.
- A declined `/lsslod store backfill start` with no running worker now reports failure and returns zero, instead of claiming the worker is already running. Backfill remains a Fabric/NeoForge feature; Paper has no backfill driver.

The shared code changes are byte-identical at source across all five lines. The command feedback delta is identical inside each line's existing Minecraft API adaptation. Exact source refs, adapted blobs and candidate port checks were refreshed and passed.

## Validation

The migration corpus compares the old `GsonBuilder` deserialization with migration for both server schemas and the client schema. It covers comments, quoted/unquoted names and values, separators, prefixes/BOM, repeated root fields and sparse arrays. Dedicated migration/persistence suites passed with Gson 2.13.2 and again with 2.10.1. Whole-file tests retain original JSON/backup bytes and adopt the generated YAML on later loads.

A real SQLite store regression seeds a dimension, reopens the store with its startup sweep deliberately held, enables backfill once, verifies that no columns are read early, then releases the sweep and observes backfill proceed without another reload. Existing tests still cover genuinely unhealthy starts, same-revision retry, off/on during a read, manual pause and shutdown receipts.

Every line uses an exact `CI=true -Pmod_version=0.16.0` build with its required JDK. Common/platform JUnit, Fabric and NeoForge server gametests, all three loader builds, VSS variants and supported private-Xvfb client gametests passed. Heavy checks were serialized without Windows foreground input.
