## DH terrain on by default (user decision 2026-10-10)

"Allow DH Server Terrain" (`lod.source`) now defaults to `distant_horizons` on all five lines. Native LSS still wins on any server that offers it.

- **Settings.** The experimental sidecar stores only nondefault values. A fresh client has no sidecar and allows DH. Turning the option off writes `source: lss` to the sidecar only. An older development sidecar that says `distant_horizons` now repeats the default and is dropped on the next save. The main client file still never carries an experimental key. Tests pin each of these.
- **Product fix found by the gate.** `MenuContext` used `!DhClientSession.selected()`, which is true with no connection once the default is on. On the title screen the Xaero map tooltip then said the option had no effect "while using DH". The context now reports DH only on a live connection that selected it. `LSSConfigMenuTest` caught it and `DhClientSessionTest` pins both sides.
- **Behaviour read from code and tests.** Native LSS wins, including a server that offers native service but disables it. On a server without a DH channel the session waits and sends nothing. With the DH client mod installed the adapter stays idle (`CLIENT_MOD_CONFLICT`). Without Voxy no DH session starts. Reception off pauses DH. With the option on, Fabric advertises the optional `distant_horizons:msg` channel on every connection, and NeoForge registers it at startup. Turning the option off on NeoForge stops DH on reconnect, but the channel stays advertised until the game restarts.
- **Live default path (26.2).** A new rig option, `test-fixtures/dh-live --source-unset`, writes no `lod.source` and no sidecar. The live jars were byte-identical to the gate jars, and all four cases passed:

| Case | Result |

| Fabric (Voxy), official DH 3.3 | READY; 101 requests, 933 columns, 4.2 MB; Voxy readback 53,760 samples; 32 receipts |
| NeoForge, vanilla server | NO_SERVICE (no DH channel); 0 requests in 30 s; connection stayed up |

No sidecar existed in any client config directory after the runs. The evidence is in `build/dh-ports/default-on/` in the main checkout.

  - The 1.21.10 and 1.21.11 NeoForge jars carry the compiled and tested adapter, but neither their notes nor their tooltips promise NeoForge DH.

## Hosted checks (2026-10-10)

The five release branches were pushed together, and PRs #317–#321 were opened without merging. Catalog, settings, client-gametest and build checks passed on all five PRs.

The first 1.21.1 build attempt failed in the isolated harness-fixture suite. `test_sigterm_reaps_actual_game_and_releases_lock` saw the lock still held right after a SIGTERM'd fake run exited. The same bytes passed on the other four lines and in every local gate. The log was preserved and the failed job re-run once, which passed. The failure is recorded as an unresolved timing candidate in `docs/operations/test-flakes.md`.

The second hosted round, after the record commit, failed once on 26.1 (run 38079635003). `DhClientSessionTest.anUnreadableDestinationTrustsReceiptsOnceAndNeverPolls` hit an IOException while JUnit deleted the `@TempDir`. This was a real test race: stopping a session queues a forced receipt save on the background receipt thread, and the test cleanup did not wait for it. The cleanup now drains receipt IO after disconnect, with the same three lines on every line. Product code is unchanged, so the jar class bytes and the gate results above still describe the release. The 120 `DhClientSessionTest` cases passed on all five lines after the fix. The catalog was re-pinned to the fix commits, and the explicit five-ref check reports no issues.

The DH default flip restaged all five branches: the flip, the menu-context fix, short release notes and README/contributor-guide updates, then a re-pin. The explicit five-ref check reports no issues. Hosted checks on the restaged heads run after this record is pushed.

## Known limits

- DH terrain is a block-resolution approximation. It is on by default and is not endorsed by the Distant Horizons team. DH 3.2.x servers are not supported, and the DH client mod must not be installed alongside.
- Existing Xaero first-spawn gaps, region-boundary shading seams and shader/LOD-depth limitations remain.
- Folia remains experimental, and is unavailable on 1.21.1 and 1.21.10. NeoForge remains best-effort; its distant-player rendering exists only on 1.21.1.
- No new performance or native-platform coverage is claimed beyond the DH matrices above.
