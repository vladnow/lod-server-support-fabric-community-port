# Как опубликовать порт

Проверено 11 октября 2026 года. Названия кнопок могут меняться; ссылки ведут на официальные инструкции и правила. Публикация здесь не выполнялась.

## Где можно публиковать

| Площадка | Вывод для этого проекта |
|---|---|
| GitHub, публичный репозиторий и Releases | MIT разрешает публиковать исходники и собранный мод с сохранением авторства и лицензий. Это наиболее прямой вариант; не заявляй, что являешься автором исходного мода. |
| CurseForge, Minecraft Mods | Правила допускают разрешённые лицензией форки с указанием оригинала и объяснением изменений. Можно подать этот порт на проверку; одобрение решают модераторы. |
| Modrinth | MIT сама по себе не гарантирует одобрение повторной загрузки. Правила требуют разрешения автора либо существенно отличающегося форка. Для версионного порта безопаснее получить явное письменное разрешение на свой аккаунт. Указанное upstream разрешение XANTHA не распространяется автоматически на тебя. |
| Собственный сайт / ссылка на GitHub Release | Распространение MIT-кода разрешено с уведомлениями об авторстве и лицензиях. Не включай Minecraft server/client JAR и отдельный Voxy renderer. |
| Hangar / SpigotMC | Подготовлен Fabric-мод, не Paper/Spigot-плагин. Не загружай его как плагин: он не предназначен для папки `plugins`. |

«Можно по лицензии» и «гарантированно пройдёт модерацию» — разные вещи. Честно гарантировать решение сторонней площадки нельзя. Для начала рекомендую GitHub, затем CurseForge; Modrinth — после разрешения VoX или письменного подтверждения модерации.

Источники: [MIT upstream](https://github.com/VoX/lod-server-support/blob/main/LICENSE), [upstream redistribution](https://github.com/VoX/lod-server-support#redistribution), [правила CurseForge](https://support.curseforge.com/support/solutions/articles/9000197279-moderation-policies), [правила Modrinth, разделы 4 и 6](https://modrinth.com/legal/rules).

## Результат этой подготовки

Собраны два альтернативных JAR, архив полного проекта и sources.jar. Подтверждено: 2869 обычных тестов, 80 серверных GameTests, запуск выпускного VSS JAR и клиентский сценарий с отдельной локальной Voxy 26.3/Sodium. 12 тестов пропущены явно. Полная визуальная проверка двух игроков и сторонних интеграций не завершена, поэтому для первой публикации оставляй **Alpha / Pre-release**. Точные версии и границы проверки — в `verification/TEST-REPORT.md`.

## 1. Подготовь файлы

1. Открой папку проекта и `dist`. Основной файл — `voxy-server-side-fabric-0.17.0-port.26.3.1.jar`. Это Fabric-мод, хотя в названии есть Server Side.
2. `lod-server-support-fabric-0.17.0-port.26.3.1.jar` — альтернативная LSS-брендированная сборка того же мода. Устанавливай и публикуй один вариант как основной. Не ставь оба одновременно.
3. Прочитай `verification/TEST-REPORT.md`. Отмечай только реально проверенные функции. Не называй стабильной сборку, у которой не завершены клиентские проверки.
4. Сохрани `LICENSE`, `THIRD-PARTY-NOTICES`, `UPSTREAM.md`, `CHANGELOG.md`, исходники и контрольные суммы. Не убирай лицензии из JAR.
5. Используй отдельное название страницы, например **LOD Server Support Community Port**, и отдельную нарисованную человеком иконку. Не выдавай страницу за официальный LSS/VSS.
6. Английское описание подготовлено в `publication/DESCRIPTION.en.md`, текст релиза — в `publication/RELEASE.en.md`. Замени ссылки на свой будущий репозиторий там, где требуется URL исходников/ошибок. Не вставляй выдуманные ссылки.
7. Загружай только мод, его исходники и документы. Не загружай папки `.gradle`, `build`, `.tools`, тестовые миры, логи с именами/адресами, API-токены, Minecraft или отдельный Voxy renderer.

## 2. Проверка перед стабильным релизом

1. Создай новый тестовый сервер Minecraft 26.3 с Java 25 и Fabric Loader 0.19.5.
2. В `mods` положи Fabric API 0.160.5+26.3 и один основной JAR этого порта. Запусти сервер и дождись `Done`.
3. Создай отдельный клиентский профиль 26.3 с Fabric, тем же Fabric API, портом и отдельно полученным совместимым Voxy. Sodium должен соответствовать 26.3; сборка компилируется против 0.9.2.
4. Подключись, проверь `/vss diag` и `/vsslod diag` (для LSS-варианта — `/lss diag` и `/lsslod diag`). Убедись, что есть соединение и передача колонок, а не только отсутствие ошибок.
5. Проверь рельеф за серверной дальностью прорисовки, перемещение, переподключение, смену измерения и обновление дальнего рельефа после изменения блоков.
6. Повтори с нужными тебе Sodium/Iris и серверными оптимизаторами. Не заявляй совместимость Moonrise/C2ME/AntiXray только потому, что она была у оригинала на 26.2.
7. Сохрани результаты и обнови описание. До этого используй Alpha / Pre-release.

## 3. GitHub: исходники

1. Войди на [GitHub](https://github.com).
2. Лучше нажать **Fork** у [оригинального репозитория](https://github.com/VoX/lod-server-support), выбрать свой аккаунт и имя `lod-server-support-26.3`. Это наглядно показывает происхождение кода.
3. На странице своего форка создай ветку `fabric-26.3` через переключатель веток. Если предпочитаешь отдельный репозиторий, создай Public-репозиторий и обязательно сохрани `UPSTREAM.md` и ссылку на оригинал.
4. Загрузи исходники проекта без локальных сборочных/проверочных данных. Для большого дерева удобнее GitHub Desktop: клонируй свой репозиторий в отдельную папку, скопируй туда подготовленные исходники, проверь список изменений, сделай Commit и Push.
5. Сохрани MIT-лицензию и сторонние уведомления. Удали или отключи оригинальные release/publish workflows: их настройки относятся к проектам VoX/XANTHA, а не к твоему аккаунту. Готовая отдельная CI-конфигурация должна только собирать и проверять этот Fabric-порт.
6. В README укажи неофициальный характер порта, требования, установку, результаты тестов и ссылки на оригинал. В About добавь краткое описание и темы `minecraft`, `fabric`, `voxy`, `lod`.
7. Проверь публичную страницу в браузере без входа. Убедись, что файлы и лицензия видны.

## 4. GitHub: скачиваемый релиз

1. В своём репозитории открой **Releases → Draft a new release**.
2. Создай тег `v0.17.0-port.26.3.1` на ветке с портом. Заголовок: `Fabric 26.3 — experimental port 1`.
3. Вставь текст `publication/RELEASE.en.md`, затем конкретные результаты из `verification/TEST-REPORT.md`.
4. Прикрепи основной VSS JAR, `SHA256SUMS.txt`, архив исходников и отчёт проверки. Альтернативный LSS JAR можно приложить с явным пояснением «выберите один». GitHub также автоматически предоставляет исходники тега.
5. Отметь **Set as a pre-release**. Нажми **Publish release**, когда описание и вложения проверены.
6. Скачай опубликованный основной JAR обратно и сравни SHA-256 с локальным файлом. В PowerShell: `Get-FileHash -Algorithm SHA256 -LiteralPath 'путь-к-скачанному.jar'`.
7. Проверь, что ссылка открывается публично и скачивание работает. Локально подготовленные файлы ещё не означают опубликованный релиз.

Официальная инструкция: [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

## 5. CurseForge

1. Войди в [панель авторов](https://authors.curseforge.com/) и выбери создание проекта, игру Minecraft и тип **Mods**.
2. Название: `LOD Server Support Community Port`, без номера игры в самом названии проекта. Summary: `Unofficial Fabric port providing distant terrain to Voxy clients.`
3. Выбери MIT, подходящие категории и свою отдельную иконку. Не копируй страницу оригинала; подготовленное описание объясняет именно этот порт.
4. Вставь английский текст из `publication/DESCRIPTION.en.md`, добавь ссылку на оригинальный проект и свой публичный GitHub с исходниками/Issues.
5. В Files загрузи основной VSS JAR. Выбери Minecraft **26.3**, загрузчик **Fabric** и тип **Alpha** до полной клиентской проверки. Не отмечай Paper/Forge/NeoForge.
6. Укажи Fabric API как обязательную зависимость. Voxy опиши как требуемый на клиенте для отображения LOD; серверному администратору он не нужен. Sodium/Mod Menu обозначай согласно реально используемому клиентскому набору.
7. В changelog вставь описание изменений и результаты проверки. Сохрани уведомления об MIT и VoX, сообщи, что это неофициальный порт.
8. Отправь проект на модерацию. Если отклонят — исправь замечания на том же проекте либо подай корректную апелляцию, не создавай дубликаты ради обхода проверки.
9. После одобрения проверь публичную страницу, выбранные версии и скачай JAR для сверки SHA-256.

Официальная инструкция: [создание проекта](https://support.curseforge.com/support/solutions/articles/9000197241-creating-and-submitting-a-project).

## 6. Modrinth

1. Сначала получи разрешение от VoX на публикацию этого Fabric 26.3-порта под своим аккаунтом. Можно самостоятельно открыть issue в оригинальном репозитории; текст запроса ниже. Я сообщение автору не отправлял.
2. Сохрани публичную ссылку или другое доказательство разрешения. При сомнениях уточни у поддержки Modrinth, удовлетворяет ли этот порт критериям форка. Простая смена версии не гарантирует «substantial divergence».
3. После разрешения войди на [Modrinth](https://modrinth.com), создай проект типа **Mod**, укажи отдельное название, MIT и собственную иконку, созданную без генеративного AI.
4. Укажи клиент и сервер: этот JAR работает на обеих сторонах, передача LOD требует установки на обеих. На обычный сервер без Fabric этот JAR не подходит.
5. Добавь собственный GitHub в Source и Issues; в описании укажи VoX, оригинал, изменения порта и границы проверки.
6. При использовании подготовленного мной текста страницы включи **Contains AI-generated content**: актуальные правила распространяют раскрытие также на описание/публикацию с AI. Не скрывай его. Правила также запрещают проекты, преимущественно созданные AI, и AI-изображения на странице; основа этого проекта — upstream, но решение принимает модерация.
7. Создай версию `0.17.0-port.26.3.1`, выбери Minecraft 26.3, Fabric, тип Alpha. Загрузи основной JAR; исходники можно приложить как соответствующий additional file.
8. В Dependencies добавь Fabric API как Required. Отдельно объясни клиентскую необходимость Voxy; не объявляй renderer обязательным на dedicated server.
9. Укажи разрешение автора, отправь на модерацию, дождись решения. После одобрения проверь страницу, скачивание и SHA-256.
